# Naver Laya Mail Triage

네이버 메일을 IMAP으로 읽어 로컬 PC에서 [Laya](https://github.com/NandhaKishorM/laya) 모델로 자동 분류하는 Windows 메일 분류기입니다. 광고, 안내, 업무, 결제·배송, 보안, 긴급 메일을 구분하고, 최종 승인 후 지정한 Gmail 주소로 요약 결과를 전송합니다. 개인정보와 메일 본문을 외부 AI API로 보내지 않는 로컬 AI 메일 분석 도구를 목표로 합니다.

분류가 끝나면 최종 승인 창을 보여줍니다. `예`를 누르면 즉시 발송, `아니오`를 누르면 취소하며, 선택하지 않으면 저장된 Gmail 주소로 **60초 후 자동 발송**합니다. 호스팅된 AI API와 브라우저 자동 로그인은 사용하지 않습니다.

**Local-first Naver mail triage powered by Laya, an open-source Jev-compatible System One decision model.**

## 주요 기능

- 네이버 IMAP 받은메일함을 읽기 전용 명령으로 조회하고, 수집 전후의 읽음 상태를 확인합니다.
- 메일을 `업무`, `개인`, `안내`, `결제·배송`, `광고`, `기타`로 분류하고 긴급도와 답장 필요 여부를 표시합니다.
- 검토 결과를 정답으로 저장합니다. 비슷한 메일에는 정답 기억과 로컬 보조 분류기를 제한적으로 적용합니다.
- 수집·분류 진행 상황과 중단 기능, 수동 수정, 선택 결과 내보내기를 제공합니다.
- 새 분류가 끝나면 발송 전 미리보기를 보여줍니다. `예`는 즉시 발송, `아니오`는 취소, 미응답은 60초 후 자동 발송입니다.
- 메일 제목·발신자·분류·긴급도만 요약 메일에 넣고 긴급 항목을 강조합니다. 원본 본문은 요약 메일에 넣지 않습니다.

## Laya와 공개 기본 분류기

이 저장소는 Laya를 개발하거나 Laya 가중치를 재학습한 프로젝트가 아닙니다. 별도로 설치한 Laya `multilingual` 체크포인트를 로컬 HTTP 서버에서 실행하고, 메일의 제목·발신자·본문 앞 1,600자로 **카테고리, 긴급도, 답장 필요 여부**를 판단하게 합니다. Laya는 대화형 LLM이 아니라 선택지와 기준을 주고 결정을 받는 비자동회귀(non-autoregressive) 결정 모델입니다. [원저장소](https://github.com/NandhaKishorM/laya)와 [다국어 체크포인트](https://huggingface.co/convaiinnovations/laya-multilingual)를 참조하세요.

최근 주목받는 [TypeSafe AI의 Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev)처럼, Laya도 상태와 명시적인 질문에서 구조화된 결정을 얻는 System One 접근을 사용합니다. Laya 원저장소는 자체 HTTP 서버의 요청·응답 형식을 **Jev-compatible**이라고 설명합니다. 이는 사용 방식의 유사성과 인터페이스 호환성을 뜻하며, 두 모델의 가중치·학습 과정·정확도·속도가 같다는 뜻은 아닙니다. 이 앱은 Jev API를 호출하지 않습니다.

`seed/public-classifier.joblib`은 이 프로젝트의 **별도 보조 분류기**입니다. `build_public_seed.py`에 직접 작성한 **가상의 한국어 메일 예시**만으로 만든 scikit-learn TF-IDF/로지스틱 회귀 모델이며, 실제 사용자 메일이나 개인 학습 결과가 들어 있지 않습니다. 이 모델은 Laya의 카테고리를 확신도 조건이 맞을 때만 보정합니다. 실제 메일에 대한 정확도 보증이나 Laya 파인튜닝 결과가 아닙니다.

사용자가 자신의 메일을 검토하고 `검토 결과 재학습`을 누르면 개인 보조 분류기가 로컬 `data/`에 저장됩니다. 이후 검증 조건을 통과한 경우 공개 기본 분류기 대신 사용됩니다. **이 개인 파일은 GitHub에 올리지 않습니다.** 분류·긴급도 규칙과 우선순위는 [개발명세서](docs/DEVELOPMENT_SPEC.md)에 정리했습니다.

## 설치 및 실행

검증 환경은 Windows, Python 3.12, Node.js 24입니다. Git과 최초 의존성·모델 다운로드를 위한 인터넷 연결도 필요합니다.

1. `setup.bat`을 실행해 `.venv`를 만들고 `requirements.txt`의 Python 패키지를 설치합니다.
2. 네이버 메일에서 IMAP을 활성화하고 2단계 인증용 애플리케이션 비밀번호를 준비합니다.
3. `run-app.bat`을 실행합니다. 모델 서버(`127.0.0.1:8000`)와 앱(`http://127.0.0.1:4327/`)이 열립니다. 첫 실행에는 Laya 체크포인트 다운로드로 시간이 걸릴 수 있습니다.
4. 앱 화면에서 네이버 주소와 앱 비밀번호를 입력해 연결합니다. `결과 받을 Gmail`에 본인의 주소를 입력하고 `수신 설정 저장`을 누릅니다.

자동 발송은 **기본 켜짐**입니다. 저장된 Gmail 주소와 네이버 메일 연결이 모두 있어야 60초 타이머가 시작됩니다. 수신 주소가 아직 없으면 자동 발송하지 않으며, 승인 창에서 주소를 저장하면 그때부터 60초가 시작됩니다. 사용자는 수신 설정의 체크박스로 이 동작을 끌 수 있습니다. 승인 창에는 남은 시간이 표시되며, 주소 변경을 시작하면 타이머가 일시중지됩니다. 브라우저 창을 닫아도 서버가 실행 중이면 타이머는 계속 진행됩니다. 앱을 재시작한 뒤 승인 대기 건이 있으면 연결 확인 후 새 60초를 부여합니다.

이후에는 `run-app.bat`만 실행하면 됩니다. 이미 정상 실행 중인 서버는 중복으로 시작하지 않습니다. `npm test`로 Node 테스트를 실행할 수 있습니다. 공개 기본 분류기를 다시 생성하려면 `.venv\Scripts\python.exe build_public_seed.py`를 실행합니다. 이 명령은 가상 예시만 사용합니다.

### 계정 연결 커스터마이징

현재도 `이 PC에 저장`을 선택하면 **각 사용자 PC의 `.env`에 저장한 본인 계정**으로 다음 실행 때 IMAP 자동 재연결을 시도합니다. 공개 저장소에 주소나 앱 비밀번호를 미리 박아 두는 방식은 사용하지 않습니다. 내려받은 사용자는 `env-config.mjs`, `server.mjs`, `mail_reader.py`를 수정해 연결 화면이나 자신의 자동 연결 흐름을 추가로 맞춤화할 수 있습니다. 어떤 방식을 택하든 본인의 인증 정보는 로컬 설정에만 두고 소스·커밋·스크린샷에 넣지 않아야 합니다. 브라우저 기반 네이버 자동 로그인은 현재 구현되어 있지 않습니다.

## 개인정보와 공개 범위

앱을 사용하면 `data/results.json`에 메일 **원문 전체**와 검토 결과가 저장됩니다. 개인 학습 파일, 모델 다운로드, 발송 기록과 로그도 `data/`에 저장됩니다. `이 PC에 저장`을 선택하면 네이버 계정과 앱 비밀번호가 평문 `.env`에 저장되고, 수신 설정을 저장하면 Gmail 주소와 자동 발송 설정도 `.env`에 저장됩니다. 네이버 계정의 앱 비밀번호 자체가 읽기 전용 권한으로 제한되는 것은 아니며, **앱의 IMAP 조회 동작**만 읽기 전용입니다.

`.gitignore`는 `.env`, `data/`, `.venv/`, Python 캐시와 화면 캡처를 제외합니다. 공개용 `seed/`에는 가상 예시 모델만 있습니다. GitHub에 올리기 전에는 이 공개본 폴더에서 `git add -n .`으로 포함 파일을 확인하고, 실제 커밋 전 `git diff --cached --name-only`를 다시 확인하세요. `git add -f`, ZIP 압축, GitHub 웹의 직접 파일 업로드는 제외 규칙을 우회하거나 적용하지 않을 수 있습니다. **사용 후 생성된 `data/`와 `.env`는 어떤 방식으로도 공개하지 마세요.**

로컬 서버는 루프백 주소에만 바인딩됩니다. 하지만 앱 API는 별도 사용자 인증이 없고 `/api/results`는 원문을 반환하므로 외부 포트 포워딩이나 공용 서버 배포용으로 설계되지 않았습니다.
